> 本文件是**编写的行为示例**，展示技能期望的交互形式；不是实时模型生成记录。

**场景**：学生给了一份 PDF，想读但不知道从哪下手。

## 第一幕：第一遍·速览（先判断值不值得读）

```
👤 D:\papers\1706.03762.pdf 帮我读论文，这篇讲什么的？

🤖 （读取 PDF：15 页，标题/摘要/图表/结论已扫）
   出卡之前先说一句：这是 Transformer 的原始论文，信息量足够出一版速览卡。

   【一句话】这篇论文用纯自注意力架构（Transformer）解决了
             RNN 无法并行、长距离依赖难传递的问题
   【问题】seq2seq 翻译逐词递推，训练慢；依赖隔得远就丢
   【方法】编码器-解码器各 6 层，全部依赖用 self-attention 表达，
           顺序信息用 position encoding 补上
   【证据】WMT14 英德 28.4 BLEU，超此前最佳 2 BLEU 以上，
           训练算力反而少 1-2 个数量级
   【判断】✅ 值得精读——你做注意力机制的课程报告，这是必读的原始出处

   要进入第二遍精读吗？还是只看某几节？
```

**注意**：速览卡之后是句号，不是下一节。第一遍是门禁——用户不确认，不开始讲正文。

## 第二幕：第二遍·精读（先诊断，再讲解）

```
👤 精读吧。注意我是为了课程报告，注意力机制我只听过名字。

🤖 先诊断两个问题，好定讲解起点：
   1. RNN / seq2seq 你学过吗？（这篇的"现状"半段全在说它们差在哪）
   2. 3.2 节的 Q、K、V 三个矩阵，你现在能猜到谁是干嘛的吗？

👤 RNN 学过一点，QKV 完全没概念。

🤖 好，最小前置包先补 30 秒，只补这两块：
   - seq2seq：编码器把句子压成一个向量，解码器从这个向量逐词吐出译文——
     整句挤一个向量，所以长句容易丢信息。
   - 注意力（Bahdanau 2014）：解码每个词时回头看原句，"按相关度加权取信息"，
     不再全靠那一个压缩向量。Transformer 是把这套"回头看"推到极致的版本。

   ——现在进 3.2 节（缩放点积注意力），按节走四步：

   ① 定位：这节定义全篇唯一的核心算子，后面所有"注意力"都是它。
   ② 讲解：把句子每个词投影成三种角色——Query（我找什么）、Key（我是什么标签）、
      Value（我实际装的内容）。每个词拿自己的 Q 和全句 K 做点积打分，
      softmax 归一成权重，按权重把全句 V 加权求和。
      一句话：每个词都开一次"检索"，检索范围是整句话。
   ③ 衔接：它解释了摘要里"更强、更快"的"更强"（全连接的依赖路径）；
      "更快"来自下一步 3.2 末尾的矩阵化——QKᵀ 一次算完全部配对。
   ④ 卡点确认：QKV 这套角色分工跟上没？跟上我们就去 3.2.2 多头。

👤 QKV 有点感觉了，像搜索引擎。继续。

🤖 （记录：Q/K/V 用"检索系统"类比讲通。下一节……）——节选到此，
   完整逐节推进见 three-pass-method.md 的四步规则。
```

## 第三幕：第三遍·硬核（逐符号，问"凭什么"）

```
👤 公式 (1) 那个 softmax(QKᵀ/√d_k)V，为什么要除以 √d_k？凭直觉除以 d_k 不也行？

🤖 好问题——这是第三遍该问的那种问题。逐符号拆，再看这个除法"凭什么"：
   - Q、K 的行向量是 d_k 维。两个独立分量的向量做点积，
     结果的方差正比于 d_k（每维贡献一点，维数越多越大）。
   - softmax 对输入尺度敏感：logits 大 → 输出趋近 one-hot → 梯度趋近 0（饱和区）。
   - 所以 d_k 大时，不缩放的点积会把 softmax 推进饱和区；
     除以 √d_k 恰好把方差拉回 O(1)，softmax 保持"软"、梯度健康。
   - 为什么是 √ 而不是 d_k 本身：目标是"方差归一"，方差按 d_k 增长，
     标准差按 √d_k——除以标准差才归一。
   论文没给这个推导（只在脚注说"假设 q·k 是均值为零方差 d_k 的"），
   这一步补全就是你的报告里可以写的点。

👤 懂了，这个我写进报告。

🤖 （记录：缩放因子用"方差增长 vs 标准差归一"讲通，用户明确表示要引用。）
```
