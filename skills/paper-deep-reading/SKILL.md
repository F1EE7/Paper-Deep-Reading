# 目标

带用户用三遍法精读学术论文：先判断值不值得读，再补齐背景逐节读懂，最后教用户批判性审读。总结只告诉你论文说了什么；三遍法教会你怎么读。

# 适用场景

- 用户给出论文：PDF 文件路径、arXiv/DOI 链接、粘贴的文本或截图
- "帮我读论文 / 这篇值不值得读 / 哪里看不懂 / 这个公式讲一讲"
- "继续读上次那篇" / "读完了，帮我出笔记"
- 读英文论文的学生与研究者，第一次接触某个领域的文献

# 第一层：输入与模式判断（必须先做，不可跳过）

## 输入通道

| 用户给的 | 怎么接 |
|---|---|
| PDF 文件路径 | 用宿主能力直接读取；超过 30 页按节分批，进度先写入记忆 |
| arXiv / DOI 链接 | 先抓摘要页；全文拿不到就走降级路径（见 `references/reader-diagnosis.md`），并明示"现在只基于 X" |
| 粘贴文本 / 截图 | 直接用；缺上下文先问出处（哪篇论文、第几节） |
| "继续" | 读记忆恢复进度，不重新开始 |

## 模式路由

| 用户意图 | 模式 | 产出 |
|---|---|---|
| "这篇值不值得读 / 快速看一下" | 速览（第一遍） | 速览卡 |
| "精读这篇 / 帮我读懂" | 精读（第二遍） | 背景诊断 → 分节讲义 → 精读笔记 |
| "这个公式/实验讲透" | 硬核（第三遍） | 逐符号推导 / 实验 critique |
| "导出笔记 / 我读完了" | 产出 | 结构化精读笔记 |
| "继续" | 恢复 | 从记忆续读 |
| 输入不是论文（习题、博客、教材章节等） | 路由拒绝 | 不硬讲；说明本技能只处理论文，指向合适的技能 |

拿不准用户要哪种深度时，先给速览卡——它本身就是后续所有模式的入口。

# 三遍法概览

**第一遍·速览**（5–10 分钟）：只看标题、摘要、图表、结论，回答四要素：解决什么问题、核心思路、凭什么信、和用户目标相关吗。产出速览卡后**停下等用户确认**，不得自动开始精读。

**第二遍·精读**：先诊断（为什么读这篇、有什么背景、卡什么），再逐节讲。每节四步：一句定位 → 讲解 → 与前后节的衔接 → 卡点确认。缺什么补什么，不整段重讲。

**第三遍·硬核**（按需）：逐符号推公式、按批判清单审实验、指出局限。标准是"假设自己是作者，每一处都能 defend"。

逐步操作细则：`references/three-pass-method.md`
背景诊断与最小前置包：`references/reader-diagnosis.md`
批判性审读清单：`references/critical-checklist.md`

# 记忆系统

**类型**：分析记忆（不参与间隔复习）。

**存储位置**：`memory/paper-deep-reading/<论文-slug>.md`，一篇论文一个文件。

**存储内容**：读这篇的目的、当前遍数与进度（到哪节）、卡过的点、有效的讲解方式。

**读/写规则**：

- **写入**：每次会话结束或模式切换时更新进度；卡点解除后记录"哪节哪个概念 → 什么讲法有效"。
- **读取**：用户说"继续"或再次提到同一篇论文时。**记忆不存在或内容与当前论文对不上时，重新询问目的与进度，不得假装记得。**
- **管理**：用户说"清除 paper-deep-reading 记忆"时，删除本目录下全部文件。

# 输出契约

**速览卡**（固定五段，顺序不可变）：

```
【一句话】这篇论文用 X 方法解决了 Y 问题
【问题】现有方法差在哪，为什么重要
【方法】核心思路（给直觉，不展开数学）
【证据】主要实验/理论结果，规模是否可信
【判断】✅ 值得精读 / ❌ 到此为止 / ⚠️ 只读某几节，理由：
```

**精读笔记**：固定 8 字段——问题 / 核心贡献 / 方法拆解 / 关键公式与直觉 / 实验与证据强度 / 局限与质疑 / 与我读它的目的的关系 / 延伸阅读。模板与填写规范见 `references/note-template.md`。
