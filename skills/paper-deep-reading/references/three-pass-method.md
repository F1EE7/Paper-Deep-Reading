# 三遍法逐步操作细则

对应 SKILL.md 的三遍概览。每一遍都按"看什么 / 问什么 / 产出什么 / 何时停"执行。

## 第一遍·速览（5–10 分钟）

**看什么**：标题、摘要、全部章节标题、图表及其说明、结论。不看正文推导。

**问什么**（四要素，在脑子里过完再写卡）：

1. 解决什么问题？现有方法差在哪？
2. 核心思路是什么？（能用一句"用了 X 手段做 Y"说出来吗）
3. 凭什么信？（实验规模、数据集、理论证明，哪个在撑）
4. 和用户读它的目的相关吗？（先看记忆里有没有这篇的目的；没有就在卡后问一句）

**产出什么**：速览卡，五段固定顺序，不得增删换序：

```
【一句话】这篇论文用 X 方法解决了 Y 问题
【问题】现有方法差在哪，为什么重要
【方法】核心思路（给直觉，不展开数学）
【证据】主要实验/理论结果，规模是否可信
【判断】✅ 值得精读 / ❌ 到此为止 / ⚠️ 只读某几节，理由：
```

**何时停**：速览卡发出后**必须停**，等用户确认"进入精读 / 只读某几节 / 到此为止"。速览是门禁，不是全流程的第一格——用户没有确认，不得开始讲正文。

## 第二遍·精读

**看什么**：按节通读正文，忽略大部分数学证明细节（能看懂"这步在干嘛"即可）。

**问什么**：讲解之前先诊断（问题库见 `references/reader-diagnosis.md`）——用户为什么读这篇、有什么背景、上次卡在哪（读记忆）。之后每节自问：这节在整篇论证里承担什么角色？关键结论是靠什么支撑的？

**产出什么**：分节讲义。每节固定四步推进：

1. **定位**：一句话说这节在干嘛
2. **讲解**：关键内容，术语首次出现必须给直觉解释
3. **衔接**：这节和上一节、下一节怎么接上
4. **卡点确认**：问用户"这节跟上了吗"。卡住 → 用最小前置包补（见 `references/reader-diagnosis.md`），补完重新确认；用户确认懂了才进下一节

**何时停**：全部节过完、用户确认后，提示"可以出精读笔记"（模板见 `references/note-template.md`）。用户中途离场 → 把进度写入记忆再结束会话。

## 第三遍·硬核（按需进入）

**看什么**：逐公式、逐实验读。假设每个 claim 都可能是错的。

**问什么**：

- 公式：每个符号哪来的？这步推导凭什么成立？换个写法还成立吗？
- 实验：结论真的被实验支撑吗？逐条过 `references/critical-checklist.md`。
- 结构：如果我是 reviewer，这篇的 weak point 在哪？

**产出什么**：逐符号推导链（每个等号/不等号一句"凭什么"）、实验 critique、局限与质疑列表。这些内容直接填进精读笔记的"关键公式与直觉"和"局限与质疑"两栏。

**何时停**：用户拿回主导权——硬核模式以回答完用户指定的对象（某公式/某实验/某节）为终点，不自动扩展到全文。

## 长文分批与进度规则

- 论文超过 30 页（或 PDF 解析不完整）时：**不整篇硬灌**。先出速览卡，然后按节分批精读，每批 2–3 节。
- 每批开始前，先把进度写入记忆（当前遍数、读到哪节），再继续——保证会话随时中断随时能续。
- 用户回来说"继续"时：读记忆 → 报上次进度（"上次读到第 X 节，卡在 Y"）→ 确认后接着讲，不重讲已确认的节。
- 记忆不存在或对不上当前论文：重新询问目的与进度，不得假装记得。
