# 批判性审读清单

对应三遍法第三遍。用法：不要求每次全过一遍——按用户指定的对象（实验/方法/写作）取对应那组；硬核精读整篇时三组全过。每条都是"可勾选项 + 怎么核"。

## 一、实验类

- [ ] **Baseline 公平吗**——怎么核：对比方法用的是它论文里的最优配置还是弱化版？调参预算对等吗？
- [ ] **有消融实验吗**——怎么核：去掉论文的关键组件（如某个模块、某项损失）结果掉多少？没有消融，"组件有效"就只是声明。
- [ ] **数据泄漏可能吗**——怎么核：测试集和训练集是否同源/有时间重叠？预处理统计量是不是在全集上算的？
- [ ] **指标和结论匹配吗**——怎么核：结论说"更好"，指标是主指标还是挑出来的？提升幅度和方差比过吗（多 seed 吗）？
- [ ] **规模撑得起结论吗**——怎么核：只在 1–2 个小数据集/任务上验证，却下"通用"结论？
- [ ] **对比的是同期最好吗**——怎么核：baseline 里有没有近两年方法，还是全是老方法？

## 二、方法类

- [ ] **假设成立吗**——怎么核：方法依赖的假设（如分布、无噪、可微）在它自己要解决的场景里成立吗？
- [ ] **复杂度声明诚实吗**——怎么核：理论复杂度和实际跑的时间/显存对得上吗？有没有回避空间开销？
- [ ] **核心设计有依据吗**——怎么核：关键选择（超参、结构、损失形式）是消融/理论推出来的，还是"我们试了下效果不错"？
- [ ] **可复现吗**——怎么核：超参、实现细节、随机种子给全吗？代码/附录在吗？
- [ ] **新颖性成色**——怎么核：把新组件换成已知方法，还成立吗？和最近邻工作的差异是本质的还是表述的？

## 三、写作类

- [ ] **claim 与 evidence 对齐**——怎么核：摘要/结论里每个"显著/优于/首次"，正文有没有对应实验或证明？语气比正文强吗？
- [ ] **Related work 缺漏**——怎么核：有没有明显该比而没比的线路？引的都是自己人或只有自家工作？
- [ ] **图表诚实**——怎么核：坐标轴截断了吗？误差棒给了吗？图例和文字描述一致吗？
- [ ] **定义先行**——怎么核：核心术语第一次用之前定义了吗？"性能提升"这种模糊说法后来给准数了吗？
- [ ] **局限承认了吗**——怎么核：作者自己列了哪些 limitation？没列的往往比列了的更值得问。

## 使用纪律

- critique 要落在**具体位置**：第 X 节的哪个 claim、表 Y 的哪个对比。不写"实验不够充分"这种空话。
- 每条 critique 标注严重度：**致命**（结论不成立）/ **重要**（结论要打折）/ **疑问**（值得查证）。
- critique 直接填进精读笔记的"局限与质疑"栏；不改变"速览判断"，除非确有致命伤。
