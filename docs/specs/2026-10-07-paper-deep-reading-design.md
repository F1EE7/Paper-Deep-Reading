- 日期：2026-10-07
- 状态：待用户审阅

## 1. 目标与非目标

### 目标

做一个可发布到 GitHub 的单技能项目 `paper-deep-reading`：教 agent 用**三遍阅读法**带用户精读学术论文——先判断值不值得读，再诊断背景缺口做针对性讲解，最后批判性审读；每篇留下结构化精读笔记，支持跨会话续读。

**语言**：技能内容（SKILL.md、references、demo、evals）中文为主，术语与论文名保留英文；README 双语。与既有套件一致。

### 非目标（YAGNI）

- 不做文献检索、跨论文综述、知识库索引（姐妹技能的活）
- 不写 Python 处理脚本；PDF 解析依赖宿主 agent 原生能力
- 不做间隔复习引擎（已有套件负责"学会知识"，本技能只负责"读文献"）
- 不支持批量多论文管理

## 2. 用户与场景

**目标用户**：需要读英文论文的学生/研究者（CS 方向为主），第一次面对论文不知道怎么读、读得慢、读完记不住。

**典型触发**：

- "帮我看看这篇论文" / "这篇值不值得精读？" / "读不懂这个公式" / "继续读上次那篇" / "读完了，出笔记"

## 3. 方法论骨架：三遍阅读法

基于 Keshav 三遍法（How to Read a Paper），结合套件"先诊断，再讲解"理念改造：

### 第一遍·速览（5–10 分钟）

看：标题、摘要、章节标题、图表、结论。
问（四要素）：解决什么问题？核心思路是什么？凭什么信？和我的目标相关吗？
产出：**速览卡**（格式见 §6.1）+ 明确的"值得/不值得精读"判断及理由。用户确认后才进入第二遍。

### 第二遍·精读

逐节拆解，但**讲解前先诊断**：问清读这篇的目的、已有背景，识别前置缺口，给**最小前置包**（只补卡住的部分，不整段重讲）。公式以"看懂每步在干嘛"为标准。

### 第三遍·硬核（按需）

虚拟重现：逐符号推导公式（推导链验证）、批判实验（对题 checklist）、指出局限与可质疑处。

```

├── references/

│   ├── reader-diagnosis.md     # 背景诊断问题库 + 最小前置包方法 + 降级策略
│   └── note-template.md        # 精读笔记模板与填写规范
└── memory/paper-deep-reading/
    └── <示例论文>.md            # 记忆格式示例（house style：随技能带一个样例）
```

### SKILL.md frontmatter

```yaml
name: paper-deep-reading
description: 适用于读学术论文、文献精读。用户给论文（PDF/链接/粘贴）说看不懂、
  帮我读、值不值得读、继续读、读完出笔记，或指名单节/公式要讲透时使用。
  三遍法：先速览判断价值，再诊断背景逐节精读，最后批判性审读，产出结构化笔记。
```

description 必须包含触发词（读论文/文献/看不懂/值不值得读/继续读/出笔记），保证路由命中率。

## 5. 输入处理与模式路由

### 输入通道

| 通道 | 处理 |
|---|---|
| PDF 文件路径 | 宿主原生读取；超长（>30页）按节分批，进度记入记忆 |
| arXiv/DOI 链接 | 先抓摘要页；全文不可得则降级：摘要+图表说明+请用户粘贴关键节，并明示"现在只基于 X" |
| 粘贴文本/截图 | 直接用；缺上下文先问出处 |
| "继续" | 读记忆恢复进度 |

### 模式路由（SKILL.md 第一层判断）

| 用户意图 | 模式 | 产出 |
|---|---|---|
| 值不值得读/快速看下 | 速览 | 速览卡 |
| 精读/帮我读懂 | 精读 | 背景诊断→分节讲义→精读笔记 |
| 单节/公式/实验讲透 | 硬核 | 逐符号推导或实验 critique |
| 导出笔记/读完了 | 产出 | 结构化笔记文件 |
| 继续 | 恢复 | 从记忆续读 |
| 非论文输入 | 路由 | 礼貌拒绝，指向对应技能（如解题类） |

## 6. 输出契约

### 6.1 速览卡（固定结构）

```
【一句话】这篇论文用 X 方法解决了 Y 问题
【问题】现有方法差在哪，为什么这个问题重要
【方法】核心思路（给直觉，不展开数学）
【证据】主要实验/理论结果，规模是否可信
【判断】✅ 值得精读 / ❌ 到此为止 / ⚠️ 只读某几节，理由：
```

### 6.2 精读讲义

按节推进，每节包含：这节在干嘛（1 句）→ 关键内容讲解 → 和前后节的衔接 → 本节卡点确认（用户说懂了才推进）。

### 6.3 精读笔记（note-template.md 定义的固定字段）

问题/贡献/方法拆解/关键公式与直觉/实验与证据强度/局限与质疑/和我读它的目的的关系/还该读什么。

## 7. 记忆系统（house style）

- 位置：`memory/paper-deep-reading/<论文-slug>.md`
- 内容：读它的目的、当前遍数+进度（到哪节）、卡过的点、有效的讲解方式
- 写入：每次会话结束或模式切换时更新进度
- 读取：触发"继续"或再次提到同一篇时
- 管理：用户说"清除 paper-deep-reading 记忆"即删除全部

## 9. Evals 规格（每核心行为至少 1 例）

| # | 输入 | 期望行为 |
|---|---|---|
| E1 | 链接+"帮我看下这篇" | 先出速览卡四要素，不直接全文总结 |
| E2 | 速览请求 | 速览卡末尾有明确判断+理由 |
| E3 | 精读请求 | 讲解正文前先出现≥2 个背景诊断问题 |
| E4 | 单个公式讲透 | 逐符号解释+推导链，引用上下文 |
| E5 | "继续" | 从记忆恢复遍数与进度 |
| E6 | "读完了" | 提示导出笔记，笔记字段完整 |
| E7 | 非论文输入（数学题） | 拒绝并路由，不硬讲 |
| E8 | 只有摘要可得 | 明示降级范围，不编造正文内容 |

评分标准按"必须行为/禁止行为"双清单打分（与上仓库 rubric 风格一致）。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 宿主无法读 PDF/抓不到全文 | 降级路径写进 SKILL.md 与 reader-diagnosis.md，明示信息边界 |
| SKILL.md 过长失去路由效率 | 主体 <200 行，细则全部下沉 references |
| 与上仓库记忆机制不一致造成用户困惑 | 格式与清理口令完全沿用 house style |
| WSL/Windows 行尾混乱 | `.gitattributes` 强制 `* text=auto eol=lf`（md/py） |
