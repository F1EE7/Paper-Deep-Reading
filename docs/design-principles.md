# 设计原则

本仓库设计决策背后的原则。改技能前先读这页——新内容应服从这些原则，或作为对这些原则的显式修订进入 spec。

## 1. 先诊断，再讲解

模型拿到论文最常见的失败模式是"默认读者是自己"：要么整段复述，要么从读者已有的知识开讲。本技能把诊断做成硬性前置——精读前必须问目的/背景/卡点，讲解中缺什么补什么。诊断问题库在 `reader-diagnosis.md`，产出（用户目的、有效讲法）写入记忆。

代价是第一条回复慢一点。值得：讲错的起点比慢更贵。

## 2. 三遍法是门禁，不是流程图

第一遍速览产出的不是"概览"，是**决策**：值得精读 / 到此为止 / 只读某几节。卡片发出后必须停——用户没有确认，禁止自动进入第二遍。把选择权还给用户，这是技能和"总结器"的分界线。

## 3. 渐进披露：入口精瘦，细则下沉

SKILL.md 保持 <200 行：路由、概览、记忆规则。所有"怎么操作"的细节下沉到 4 个 references，agent 需要时才读。这保证触发时上下文开销小、细则可独立修订而不动入口。CI 检查行数上限（`scripts/check_skill.py` C2）。

## 4. 诚实边界：信息不完整时明示，禁止编造

全文抓不到 → 明说"只基于摘要"；论文没写的推导 → 声明"这是补全"；记忆缺失 → 重新询问而不是假装记得。任何"我没有的内容"只有一个合法动作：请用户提供，或承认看不到。E8 是这条的一票否决门。

## 5. 产出要可验证

速览卡五段固定、笔记 8 字段固定、推导每步带"凭什么"——固定结构让用户能一眼核对是否完整，也让 CI 能机器检查（字段逐字一致性进 C4）。自由文本留给讲解本身，骨架不自由。

## 6. 记忆服务连续性，不服务监控

记忆只存四样：读它的目的、进度、卡点、有效讲法。目的为了续读和笔记回扣；讲法为了下次少试错。不存用户画像，不做学习分析。清除口令一句话生效（见 SKILL.md 记忆系统）。

## 7. 证据诚实声明

README 的 demo 是编写的行为示例，不是实时模型记录。eval 是行为回归门禁，不是教学效果证明。宣传语只能声称"技能规定了什么行为"，不能声称"用户因此学会了什么"——后者需要真实实验。
